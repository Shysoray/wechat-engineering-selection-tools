## 1. 交接任务简报

**Role：** scoped implementation worker，因为下一项目需要在受控范围内完成数据取证、数据库修复、匹配策略和结果 UI 实施。

**Goal：** 通过知识库中全部相关品牌目录 MD，彻底核对小程序现有全品牌型号库与 VIGOUR 对标；修复缺失、伪型号、错误归一化、错误目标族、冲突映射和尺寸误判；使所有有目标型号的最终结果显示适用尺寸的源值、VIGOUR 值、差值、公差与证据状态。

**Context：** 当前运行库共 `15,280` 条品牌映射，其中 `11,623` 条有可用 VIGOUR 目标；仅 `116` 条带结构化尺寸证据，且全部属于 UNILOK。其他六个品牌的结构化尺寸证据均为 `0`。该数量是交接时的只读盘点基线，下一项目开始时必须重算。

**Allowed actions：** 读取知识库 MD、页级 MD、manifest 和必要的原 PDF；修改小程序中的取证/生成/匹配/结果/UI/测试文件；生成 JSON、CSV、Markdown 审计产物；运行离线测试和小程序预览验证。

**Ownership：** 下一项目拥有管接头对标的数据证据层、生成器、运行时展示和其测试。不拥有减压阀、Cv、兼容性、APTECH 等无关功能，不得顺手重构。

**Forbidden actions：** 不修改 `MarkItDown-KB` 中的 MD/PDF/审计证据；不使用网络二手资料替代用户目录；不伪造缺失尺寸或将缺失值写成 `0`；不直接手改生成的大型 JS 数据库；不删除或覆盖用户现有脏工作区改动；不在未取证前批量把 amber 结果改成绿色。

**Output format：** 每阶段先交付机器可读证据和异常清单，再交付代码修改；最终提供覆盖矩阵、修复清单、人工复核队列、全量测试报告和前后对比截图。

**Stop condition：** 目录品牌归属不能证实、MD 表格错位而原 PDF 仍无法辨读、产品族关键尺寸/公差尚未决策、或现有用户改动与本项目冲突时，停止对该族的自动绿色判定，记入人工复核队列，不得猜测。

## 6. 产品族比较规则

### 6.1 不能全库强套三个尺寸

当前“总长、壁厚、插入长度”只是 gland/焊接端的起点。下一项目必须先建 `family-comparison-rules.json`，每个产品族定义自己的必比字段。

| 产品族 | 必比尺寸/参数 | 结构硬门槛 | 暂定公差用法 |
|---|---|---|---|
| 长/短 gland、焊接 gland | 总长、插入/轴向长度、管外径、管壁厚、密封面规格 | 公/母、长/短、焊接类型、管端尺寸 | 总长 `≤1.0 mm`；壁厚 `≤0.005 in`；插入/轴向 `≤1.0 mm` |
| 直通/异径焊接件 | 端到端、大/小端 OD、壁厚、中心到端 | 对接/承插焊、异径方向 | 待从目录和用户规则确认，不得默认使用 1 mm |
| 弯头/三通/四通 | 中心到端 A/B/C、端径、壁厚 | 支路/主管方向、角度 | 按类型分定公差 |
| 卡套直通/异径/转接 | 总长、对边尺寸、管 OD、螺纹规格/密封形式 | 螺纹类型、公母、管端方向 | 螺纹不用长度公差代替；必须精确一致 |
| 穿板件 | 总长、最大板厚、安装孔径、对边尺寸 | 穿板结构必须一致 | 板厚/孔径单独设公差 |
| 垫片/盲垫片 | OD、ID、厚度 | 材质、镀层、盲/通孔 | 厚度需单独公差，禁止用“名义规格相同”替代 |
| 螺母/压紧件 | 螺纹、总高、对边尺寸 | 内/外螺纹、高流量/标准 | 螺纹必须精确；长度公差待定 |
| Cap/Plug | 密封面规格、总长/高度、特殊孔/软管变体 | Cap 与 Plug 不得互换 | 按目录实值定义 |
| 限流/过滤/特殊件 | 孔径、精度、流向、外形尺寸 | 特殊功能必须精确一致 | 孔径缺失直接待确认，不可绿色 |

### 6.2 公差配置要求

- 暂定 `1.0 mm / 0.005 in / 1.0 mm` 必须进入版本化配置，不得散落在生成器、测试和 UI 文案中。
- 每个公差项需有 `ruleId`、适用产品族、尺寸字段、单位、阈值、开/闭区间、版本和决策来源。
- 边界值用整数量级归一化比较（如 μm 或 1e-6 in），避免浮点误差导致 `1.0000000001 mm` 边界反转。
- 英寸壁厚可同时显示 in/mm，但判定必须在统一归一化单位上完成。

## 阶段 2：全品牌型号清单与解析取证

**目标：** 得到“目录真实型号”全集，先解决型号库有无问题。

- [ ] 异常型号不直接删除；分类为表头/页码污染、列串接、尺寸文字粘连、OCR 错字、合并产品族 token。
- [ ] 对 OCR/MD 低置信度型号回查原 PDF，不允许低置信度直接进入可搜索库。
- [ ] 与现有 `fittingDatabase.js` 及 `tubeFittingSupplementalDatabase.js` 做全外连接审计。

**必须输出的异常类型：**

1. `catalog_missing_in_runtime`：目录有、运行库缺失。

3. `normalization_collision`：不同原始型号归一到同一 key。
4. `parser_artifact`：页码/尺寸/表头泄漏进型号。
5. `duplicate_mapping`：同一品牌型号对应多个不兼容目标。

## 阶段 4：产品族对齐、差值计算与全库异常审计

**目标：** 先生成尺寸比较证据，再根据证据决定映射状态。

- [ ] 查找尺寸超差却绿色、尺寸证据缺失却宣称精确、总长接近但轴向/中心距大幅不同、壁厚单位错转、管 OD 与密封面规格混用。

**必须输出的审计问题：**

**产物：** `mapping-dimension-evidence.json`、`mapping-audit.csv`、`brand-family-coverage.csv`、`manual-review-queue.csv`。  
**验收：** 每条有目标映射都有比较状态，不存在默认空状态。

## 阶段 6：最终结果显示尺寸差异

- [ ] 差值为 `0`：显示 `0`，不省略。
- [ ] 无证据：显示“目录尺寸未建立”，并区分源目录缺失、VIGOUR 目录缺失和尚未提取。

## 8. 下一项目必须先向用户确认的决策

下列决策不得由实施任务默认扩大；可先完成证据提取，但在确认前不得用于绿色判定。

| 决策 | 需确认内容 | 暂定处理 |
|---|---|---|
| 产品族关键尺寸 | 每个族哪些尺寸是硬门槛，哪些仅提示 | 未确认必比字段的族不得绿色 |
| 公差 | 除 gland 外的端到端、中心距、OD/ID、垫片厚度、板厚/孔径公差 | 暂不沿用 1 mm/0.005 in |
| 无尺寸证据的候选 | 是否允许显示目标型号 | 允许显示但必须为 amber、不能直接复制为已匹配 |
| 单位显示 | 保留目录原单位，还是同时显示 mm/in | 判定用归一化单位，UI 先显示目录原单位 |
| 相对差 | 哪些尺寸需显示百分比 | 只作审计字段，不参与当前阈值判定 |
| 多目标映射 | 是显示多个可选目标，还是只显示首选 | 保留结构化多目标，屏幕只突出有证据的首选 |

## 9. 建议的执行顺序与任务切分

下一项目应保持一个主责人贯穿数据语义，可按下列顺序分小任务；同一时间不得多人同时修改 `build_fitting_database.py`、`resultPolicy.js` 或 `index.wxml`。

1. **只读盘点：** 完成阶段 0—1，冻结源注册。
2. **证据层：** 完成阶段 2—3，交付源/目标型号与尺寸证据，不改生产库。
3. **独立审计：** 在阶段 4 完成后先审查异常清单和产品族规则，通过后才允许修库。
4. **数据实施：** 完成阶段 5，重生成库并稳定 schema。
5. **UI 实施：** 完成阶段 6，只消费已稳定 schema。
6. **独立验证：** 完成阶段 7—8，对证据、代码、UI 和历史问题做最终复核。
